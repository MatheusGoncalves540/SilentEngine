# 06 — Integrated AI

## 1. Model of the world

The AI is an **agent loop inside the engine process**. It has:

- A **Tool API** (same one the editor uses).
- A **permission manifest** that gates tools.
- An **undo stack** shared with the editor.
- A **budget** (tokens/min, wall-clock per task).

## 2. Tool API

Every tool is a struct implementing:

```rust
pub trait Tool {
    fn schema(&self) -> ToolSchema;                 // name, description, JSON schema
    fn requires(&self) -> &[Capability];            // e.g. FsRead("assets/**")
    fn call(&self, ctx: &mut App, args: Value) -> Result<Value, ToolError>;
}
```

Registered via `app.add_tool(Box::new(MyTool))`. Editor UI auto-generates an
invocation form from `schema()`. AI uses the same registry.

### Core tools (v0.1)

| Tool | Capability | Purpose |
|---|---|---|
| `fs.read_file` | `fs:read:<glob>` | Read text file |
| `fs.write_file` | `fs:write:<glob>` | Write text file (undoable) |
| `fs.edit_file` | `fs:write:<glob>` | Line-based edits |
| `fs.list_dir` | `fs:read:<glob>` | List directory |
| `scene.list_entities` | `scene:read` | Enumerate entities + component names |
| `scene.inspect` | `scene:read` | Dump one entity as RON |
| `scene.mutate` | `scene:write` | Apply patch (undoable) |
| `scene.spawn` | `scene:write` | Spawn prefab (undoable) |
| `build.run` | `build` | `cargo build` in project |
| `game.run` | `run` | Launch game headless/headed |
| `game.screenshot` | `render:read` | PNG of a camera pose |
| `metrics.query` | `metrics:read` | Query any registered metric |
| `undo.last` | (implicit) | Revert last mutation |
| `git.diff` | `fs:read` | Get diff of working tree |

## 3. Permission manifest

Every project has `permissions.ron`:

```ron
PermissionsV1(
    grants: [
        (tool: "fs.read_file", arg_glob: "assets/**"),
        (tool: "fs.write_file", arg_glob: "plugins/**"),
        (tool: "fs.write_file", arg_glob: "assets/**"),
        (tool: "scene.write"),
        (tool: "build.run"),
    ],
)
```

Rules:

- Tool call with no matching grant → rejected, surfaced in editor. **Never**
  silently fall through.
- `fs:write:*` requires commit-style undo. All write tools push to undo stack.
- Agent cannot call `plugin.install` without explicit user approval UI.

## 4. Undo stack

Shared `CommandStack` in `App`:

- Every mutating tool returns a `Command` (do/undo).
- Editor and AI both push to the same stack.
- `undo.last` pops and applies. `redo` re-applies.
- Stack is bounded (configurable; default 1000). Overflow discards oldest with a
  warning.

## 5. Agent loop

```
loop {
  budget.check()?;
  msg = model.send(context + tool_schema)?;
  if msg.is_tool_call() {
    let result = tool_registry.call(msg.tool, msg.args)?;
    context.push(result);
    continue;
  }
  break with msg.text;
}
```

Context includes:

- System prompt (engine API, style guide, current project tree).
- Rolling window of last N tool calls + results.
- Optional: `scene.inspect` dump of the current selection.

## 6. Rules

- **AI never runs `unsafe`.** It can generate WASM plugins (compiled via a
  sandboxed pipeline), never native code.
- **AI never installs a plugin without approval.** `plugin.install` is always a
  user-gated tool.
- **AI never bypasses undo.** Every mutation goes through `CommandStack`.
- **Prompt injection awareness**: file content read by the AI is treated as
  *data*, never as instructions. The system prompt asserts this and the tool
  results are wrapped in `<file>...</file>` markers that the model is told to
  not interpret.

## 7. Metrics (mandatory)

- `ai.tool_calls` (counter, per tool)
- `ai.tool_errors` (counter, per tool)
- `ai.tokens_in` (counter)
- `ai.tokens_out` (counter)
- `ai.loop.ms` (histogram)
- `ai.undo_ops` (counter)
- `ai.permission_denied` (counter)
